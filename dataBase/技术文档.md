### 2.2 各层技术详解

#### 第 1 层：数据采集

**组件：** Python 3.10 + kafka-python 2.0.2

**实现：** `finance_kafka_producer.py`

```python
# 核心流程
1. 加载 5 个 CSV 文件到内存
2. 5 个品种轮询，每个品种每次发 1 条
3. JSON 序列化，gzip 压缩
4. 通过 kafka-python Producer 发送到对应 Topic
5. 控制速率：5 条/秒（可调 --rate 参数）
6. 支持 --loop 循环模式（CSV 读完从头开始）
```

**关键配置：**
```python
acks='all'          # 等待所有副本确认
compression='gzip'  # 压缩传输
linger_ms=5         # 5ms 小批量聚合
```

**数据格式：**
```json
{
  "symbol": "GOLD",
  "timestamp": "2026-07-11 13:30:53",
  "price": 4111.50,
  "volume": 5.0,
  "bid": 4111.44,
  "ask": 4111.56,
  "spread": 0.12,
  "direction": "UP",
  "volatility": 0.000023,
  "high": 4111.63,
  "low": 4111.50,
  "event_time": "2026-07-11T13:30:53"
}
```

#### 第 2 层：消息队列

**组件：** Apache Kafka 7.4.0 + ZooKeeper

**Topic 设计：**
| Topic | 品种 | 分区数 | 副本数 |
|-------|------|--------|--------|
| gold_tick | 黄金 | 3 | 1 |
| oil_tick | 原油 | 3 | 1 |
| silver_tick | 白银 | 3 | 1 |
| copper_tick | 铜 | 3 | 1 |
| gas_tick | 天然气 | 3 | 1 |

**消费者组：**
| 组 ID | 消费者 | 用途 |
|-------|--------|------|
| spark-finance-group | Spark Streaming | Kafka → HDFS |
| logstash_finance_group | Logstash | Kafka → ES |

**Kafka 作用总结：**
1. **缓冲削峰：** Producer 和生产者和消费者的处理速度不匹配时不会阻塞
2. **解耦：** Producer 和 Consumer 互不依赖
3. **多播：** 同一数据被两个消费者组独立消费
4. **持久化：** 消息在 Kafka 中保留一段时间，消费者可以回溯

#### 第 3 层：实时计算与数据管道

##### 3.3.1 Spark Structured Streaming

**组件：** Apache Spark 3.3.3 (Python/PySpark)

**实现：** `finance_spark_streaming.py`

```python
# 核心流程
1. readStream.format("kafka") 订阅 5 个 Topic
2. from_json(value, TICK_SCHEMA) 解析 JSON
3. to_timestamp("event_time") 标准化时间
4. foreachBatch 回调中：
   a. 原始 tick 按品种写 HDFS（JSON, 按 dt 分区）
   b. 1 分钟窗口 OHLC 聚合写 HDFS
```

**OHLC 聚合算法：**
```python
# 1 分钟窗口分组
df.withColumn("minute", date_trunc("minute", event_ts))
  .groupBy("symbol", "minute")
  .agg(
    first("price").alias("open_price"),    # 开盘 = 第一笔
    max("high").alias("high_price"),        # 最高 = 最大值
    min("low").alias("low_price"),          # 最低 = 最小值
    last("price").alias("close_price"),     # 收盘 = 最后一笔
    avg("price").alias("avg_price"),        # 均价
    sum("volume").alias("total_volume"),    # 总成交量
    count("price").alias("tick_count")      # 成交笔数
  )
```

**配置参数：**
```
trigger: 10 seconds          # 每 10 秒触发一批
maxOffsetsPerTrigger: 1000   # 每批最多 1000 条
checkpoint: /tmp/spark_cp_finance  # 故障恢复检查点
executor: 2 cores, 512MB     # 单节点资源配置
```

**HDFS 输出路径：**
```
原始数据: /user/finance/raw/{gold,oil,silver,copper,gas}/dt={yyyy-MM-dd}/
聚合数据: /user/finance/agg/1min/{gold,oil,silver,copper,gas}/dt={yyyy-MM-dd}/
```

##### 3.3.2 Logstash 数据管道

**组件：** Logstash 7.17.0

**实现：** `config/logstash/kafka_to_es.conf`

```
Pipeline 三阶段：
┌──────────┐    ┌──────────────┐    ┌─────────────────┐
│  Input   │───▶│   Filter     │───▶│     Output      │
│  Kafka   │    │ date 解析     │    │ Elasticsearch   │
│  5 Topic │    │ mutate 类型转换│    │ index:          │
│  earliest│    │ ruby 衍生计算  │    │ finance_realtime│
│  offset  │    │              │    │ _metrics        │
└──────────┘    └──────────────┘    └─────────────────┘
```

**Filter 阶段计算：**
```ruby
# Ruby 脚本 — 衍生字段
spread_pct = spread / price * 100      # 价差比例%
mid_price = (bid + ask) / 2            # 买卖中间价
```

**Output 配置：**
```
index: finance_realtime_metrics
document_id: "{symbol}-{timestamp}"     # 去重
action: index
```

**四层数仓建模：**

```sql
-- Spark 写入新分区后需要同步
MSCK REPAIR TABLE ods_finance.gold_tick;
```

## 三、机器学习详解

### 3.1 模型设计

**算法：** VotingClassifier (GradientBoosting + RandomForest), soft voting

**问题类型：** 二分类 (UP=1, DOWN=0)

**训练数据：** 25 万条 tick，有效样本约 12.5 万条

**测试集准确率：** 51.82%（基准 49.59%）

### 3.2 15 个特征及其金融含义

| # | 特征 | 金融含义 | 计算方式 |
|---|------|----------|----------|
| 1 | price_lag1 | 上一条价格（惯性参考） | price.shift(1) |
| 2 | price_lag2 | 上两条价格 | price.shift(2) |
| 3 | price_chg1 | 瞬时变化率 | pct_change(1) × 100 |
| 4 | sma_cross_5_10 | 短中期趋势方向 | (SMA5-SMA10)/price × 100 |
| 5 | sma_cross_10_20 | 中长期趋势方向 | (SMA10-SMA20)/price × 100 |
| 6 | rsi_14 | 超买超卖信号 | RSI = 100 - 100/(1+RS) |
| 7 | momentum_5 | 短期动能 | pct_change(5) × 100 |
| 8 | momentum_10 | 中期动能 | pct_change(10) × 100 |
| 9 | bb_position | 价格极端程度 | (price-SMA20)/(2×std) |
| 10 | vol_ratio | 当前活跃度 | volume/SMA(volume,5) |
| 11 | vol_change | 量能变化方向 | pct_change(5) of volume |
| 12 | spread_pct | 流动性松紧 | spread/price × 100 |
| 13 | high_low_pct | 日内波动范围 | (high-low)/price × 100 |
| 14 | bid_ask_mid | 多空力量偏离 | (bid+ask)/2 - price |
| 15 | volatility | 剧烈程度放大 | volatility × 10000 |

### 3.3 实时推理流程

```
每 5 秒:
  ES 查询最新 60 条 tick (sort: event_time desc)
  → Python 计算 15 个特征
  → model.predict_proba() 推理
  → 返回 {"prediction": "UP/DOWN", "prob_up": 0.xx, "prob_down": 0.xx}
  → 前端渲染概率进度条
```

## 四、AI 智能对话详解

### 4.1 架构

```
前端聊天窗口 → POST /api/chat → FastAPI → DeepSeek API
                                    │
                              System Prompt:
                              - 5 品种基本信息
                              - 平台技术栈
                              - 回答领域限制
```

### 4.2 System Prompt 设计

模型：`deepseek-chat` (DeepSeek V4 Pro)

预设上下文：
- 5 个期货品种的名称、价格范围、单位
- 平台技术栈：Kafka → Spark → HDFS/Hive → ES → FastAPI → ECharts
- 数据规模：25 万条 tick
- 回答领域：行情分析、技术指标解读、风险评估、技术架构问答

### 4.3 API Key 管理

- API Key 保存在服务端 `config/apikey.txt`
- 前端不接触 Key，通过 `/api/config/apikey` 端点管理
- 启动时自动加载已保存的 Key
