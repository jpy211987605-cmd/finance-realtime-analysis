# 金融实时大数据分析系统 — 答辩报告

---

## 一、项目背景与目标

构建一个**端到端的金融实时大数据分析平台**，覆盖数据采集、消息队列、数据湖存储、数据仓库建模、实时计算、搜索引擎、数据服务、可视化全链路。选取黄金、原油、白银、铜、天然气 5 个期货品种，共计 25 万条 tick 级行情数据作为分析对象。

## 四、完整数据链路实现

### 第 1 步：Docker 集群部署

- 编写 docker-compose.yml，定义 12 个服务容器
- ZooKeeper → Kafka → HDFS(NameNode+DataNode) → Hive(Metastore+PG+Server2) → ES → Logstash → Kibana → Spark(Master+Worker)
- 健康检查：ZooKeeper、Kafka、NameNode、ES、PG 均有 healthcheck
- 网络：bridge 模式，容器间通过容器名通信（kafka:9093、elasticsearch:9200）

### 第 2 步：Kafka Topic 创建

- 5 个业务 Topic：gold_tick / oil_tick / silver_tick / copper_tick / gas_tick
- 每 Topic 3 分区，replication factor = 1
- auto.create.topics.enable = true

### 第 3 步：数据生产（Producer）

- Python 脚本 `finance_kafka_producer.py`
- 流程：加载 5 个 CSV 到内存 → 5 品种轮询 → 每品种每次发 1 条 → 控制发送速率 5条/秒
- Kafka 配置：acks=all（保证不丢数据）、gzip 压缩、linger_ms=5ms 小批量聚合
- 支持 --loop 循环模式（CSV 读完后重新开始，模拟持续行情流）

### 第 4 步：Spark Structured Streaming 实时计算

- **提交方式**：`spark-submit` 到 spark-master:7077，deploy-mode=client
- **消费 Kafka**：`readStream.format("kafka")`，订阅 5 个 Topic，startingOffsets=latest
- **解析 JSON**：`from_json(value, TICK_SCHEMA)` 解析 12 个字段
- **衍生字段**：mid_price = (bid+ask)/2，spread_pct = spread/price×100%
- **写 HDFS**：`foreachBatch` 回调，每 10 秒一批，按 symbol 写各自目录，按 dt 分区
  - 输出路径：`/user/finance/raw/{gold|oil|silver|copper|gas}/dt={yyyy-MM-dd}/*.json`
- **Checkpoint**：本地文件系统 `/tmp/spark_cp_finance`，保证故障恢复

**核心技术点：**
- Structured Streaming 微批处理模型，每批 maxOffsetsPerTrigger=1000 条
- foreachBatch 回调内按 symbol 分组写 HDFS，每个品种独立目录
- 与 Hive ODS 外部表 LOCATION 对齐，实现数据湖→数仓的无缝衔接

### 第 5 步：Logstash 数据管道

- **Input**：Kafka 5 个 Topic，group_id=logstash_finance_group，auto_offset_reset=earliest
- **Filter**：
  - date 解析 timestamp 字段
  - mutate 类型转换（price/volume/bid/ask/spread/volatility 转 float）
  - ruby 脚本计算 spread_pct 和 mid_price
- **Output**：Elasticsearch，index=finance_realtime_metrics，document_id=symbol-timestamp
- 约 5000+ 条实时指标持续写入

### 第 6 步：Hive 数据仓库建模

- **ODS 层（ods_finance）**：5 张外部表，JsonSerDe 解析 HDFS JSON 文件，按 dt 分区
  - `CREATE EXTERNAL TABLE ... ROW FORMAT SERDE 'JsonSerDe' LOCATION '/user/finance/raw/{symbol}'`
  - 数据由 Spark Streaming 实时写入，执行 MSCK REPAIR TABLE 识别新分区
- **DWD 层（dwd_finance）**：5 张明细表，ORC+Snappy 压缩，新增 mid_price/spread_pct/hour 衍生字段
- **DWS 层（dws_finance）**：2 张汇总表，1分钟/5分钟 OHLC 四价+成交量+波动率聚合
- **ADS 层（ads_finance）**：2 张应用表，dashboard_metrics（大屏直读）+ latest_snapshot（最新快照）

### 第 7 步：FastAPI 数据服务

**12 个 REST 端点：**

| 端点 | 功能 | 数据源 |
|------|------|--------|
| `/health` | 健康检查 | ES ping |
| `/api/symbols` | 品种列表 | 配置返回 |
| `/api/realtime/latest` | 5品种最新行情 | ES finance_realtime_metrics |
| `/api/realtime/trend` | 价格趋势时间序列 | ES，支持 symbol+minutes 参数 |
| `/api/realtime/volume` | 成交量聚合 | ES aggregation |
| `/api/realtime/risk` | 风险指标（波动率/回撤/价差） | ES 近 500 条排序计算 |
| `/api/data/stats` | 数据资产统计（行数/均价/最值） | HDFS + 数据仓库 |
| `/api/data/sample` | 数据预览（前 N 条） | 数据仓库 |
| `/api/data/search` | 价格区间跨品种搜索 | 数据仓库 |
| `/api/analysis/correlation` | Pearson 相关性矩阵 | 数据仓库 ODS 层 |
| `/api/monitor/flow` | Kafka/HDFS/ES 三端流量对比 | 各组件 API 聚合 |
| `/api/hive/stats` | Hive 数仓各层数据量 | Hive beeline SQL |

**关键技术点：**
- CORS 全开放，支持前端跨域
- ES 不可用时自动退回 mock 模拟数据，保证前端不白屏
- 延迟创建 ES 连接，30 秒内连续失败不再重试（避免阻塞）

## 五、大数据核心技术点总结

### 5.1 消息队列（Kafka）

- 5 个 Topic 分区并行，Producer 端 acks=all 保证数据可靠性
- 支持多消费者组独立消费（Spark 一组、Logstash 一组），互不影响
- Logstash consumer group LAG=0，证明实时消费无延迟

### 5.2 流式计算（Spark Structured Streaming）

- 基于微批处理模型（Micro-Batch），每 10 秒触发一次
- foreachBatch 回调内，按品种分组写入 HDFS，路径与 Hive 外部表 LOCATION 精确对齐
- Checkpoint 机制保证 Exactly-Once 语义和故障恢复
- 资源优化：2 核心、512MB executor，单节点集群可稳定运行

### 5.3 数据湖（HDFS）

- 原始数据永久存储，不丢失任何一条 tick
- 按品种分目录、按日期分区（dt=yyyy-MM-dd），便于后续按时间范围查询
- 权限 777 开放，Spark/Hive 均可读写

### 5.4 数据仓库（Hive）

- 四层建模（ODS→DWD→DWS→ADS），符合数据仓库分层最佳实践
- ODS 层使用外部表 + JsonSerDe，数据由 HDFS 管理，Hive 只映射不拥有
- DWD/DWS/ADS 使用 ORC+Snappy 压缩存储，查询性能远优于 JSON
- 通过外部表实现 Spark→HDFS→Hive 无缝衔接：Spark 写入即 Hive 可见

### 5.5 搜索引擎（Elasticsearch）

- dynamic_templates 字符串→keyword，避免 text 字段排序聚合报错
- refresh_interval=5s，近实时可见
- 支持复合查询（term filter + range filter + sort + aggregation）

### 5.6 数据分析（Hive ODS）

- 从 Hive ODS 层读取 25 万条 tick 数据，跨 5 个品种进行价格相关性分析
- 使用 Pearson 相关系数矩阵，量化品种间价格走势的关联程度
- 发现黄金-白银呈强正相关（贵金属同质驱动），原油-天然气弱相关（供需逻辑不同）
- 支持价格区间搜索，跨 5 品种快速定位异常行情

## 八、技术创新与亮点

1. **全链路覆盖**：采集→传输→计算→存储→查询→展示，6 层无缝衔接
2. **双消费者架构**：Spark 和 Logstash 独立消费 Kafka，分别写 HDFS 和 ES，互不影响
3. **流批一体**：Spark Streaming 实时写 HDFS，Hive 外部表可立即 SQL 查询
4. **Elasticsearch 索引优化**：dynamic_templates 自动将字符串映射为 keyword，避免查询报错
5. **容器化部署**：12 节点 Docker Compose 集群，一键启动，环境可复现
6. **相关性分析**：基于 Hive ODS 层 25 万条数据的 Pearson 相关系数矩阵，量化品种间价格联动
7. **数据质量保障**：Kafka acks=all + Spark checkpoint + ES bulk 写入 + API mock 回退
8. **可维护性**：脚本化运维（init_all / start_pipeline / stop_pipeline / check_all / demo_restart）
